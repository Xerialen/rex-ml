# SPEC F1.0 — behaviour cloning at the size the budget actually allows

## Why

G0.4 measured the tick budget and picked **3 hidden layers × 512 wide** (537,096 parameters,
p99 ≈ 246 µs against a 500 µs invariant). The shipped BC policy is 2 × 256 — 71,688 parameters,
7.5× smaller — and that size was inherited, not chosen. Phase 1's RL warm start should come from a
BC policy at the size we are actually going to train and ship, or the first thing RL does is throw
away the warm start and relearn at a different capacity.

`Mlp3` currently lives in `rtx-nav/src/budget_sweep.rs`, written for the sweep. It has no loader and
is not a production type. That has to change before anything can run it.

## Part 1 — Rust: make the 3-layer network a real type

- Promote `Mlp3` to a first-class type alongside `Mlp` (its own module or into `automaton.rs`;
  `budget_sweep` may re-export it, but the sweep must not be its home).
- Give it `load(bytes)` with the same discipline as `Mlp::load`: reject any length that is not
  exactly the expected float count for its const generics. A silently half-loaded network is the bug
  class this project has already been bitten by twice.
- Its `forward` must return **raw logits**, exactly like `Mlp::forward`. Per-head activation stays in
  `automaton::decode`. This is not a style preference — applying `tanh` before `argmax` is the
  original bug, and it has since recurred once in the checking tool.
- Add a parity binary **in `rtx-nav`** (not in `rex-env` — another task is editing that crate
  concurrently) mirroring `rex-env-policy-parity`: read a flat `N×14 f32` observation file, write
  `N×(8+4) f32` of logits and decoded actions.

## Part 2 — Python: train and export at the new size

- `pipeline/policy.py`'s `DiscActor` trunk is hard-coded to two `Linear(width, width)` layers. Make
  depth configurable, defaulting to the current behaviour so nothing existing changes meaning.
- Train the discrete actor at **depth 3, width 512** on the same data and objective as the shipped
  one. Same splits: train on train, tune on val, and do not touch test.
- Extend `pipeline/export_policy.py` to export the 3-layer weights in the same little-endian,
  row-major, layer-ordered format, and to write a `policy.json` describing it. Keep the 14-input /
  8-output contract exactly — only hidden geometry changes.

## Part 3 — the gate

Re-run the G0.2 parity check against the new network and the new binary, on **≥ 100,000 held-out
rows**, with the same thresholds, which are not negotiable:

| quantity | threshold |
|---|---|
| fmove / smove / jump agreement | **100.000 %** |
| dyaw max absolute difference | ≤ 1e-5 |
| logit max absolute difference | ≤ 1e-3 |

Also report, for the record, the new policy's **held-out action agreement with the human
demonstrations** versus the old 2 × 256 policy's. That is the number that says whether the extra
capacity bought anything at all before RL ever runs — and if it bought nothing, that is a finding
worth having early.

## Constraints

- Do not touch `rtx/crates/rex-env/` — another task is editing it right now.
- Do not touch `rtx-game` or anything under `bot/`.
- Never run `cargo fmt` in this tree.
- `cargo test -p rtx-nav` (currently 134 passing) must still pass.
- Do not overwrite the existing `pipeline/out/policy/policy.bin` or its `policy.json`. The 2 × 256
  policy is a measured, parity-verified artefact and stays exactly where it is; write the new one
  beside it under a distinct name.
- The H100 is free. Use it. Long runs go in the background.

## Done when

`evidence/f1.0_bc_3x512.json` holds: the training configuration, parameter count, the full parity
table, and the held-out agreement of both policies side by side. The new weights exist beside the old
ones, and both are loadable.

## Reporting

Numbers with their conditions. Report explicitly whether the larger policy is actually better at
imitation than the smaller one, including if it is not.
