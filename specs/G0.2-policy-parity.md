# SPEC G0.2 — the Rust policy must decide exactly what torch decides

## Why

`policy.bin` is the trained actor, exported from `actor_disc.pt`. Everything downstream — warm
start, RL, the live bot — assumes the Rust forward pass reproduces the Python one. That assumption
has already been wrong once: `Mlp::forward` used to apply `tanh` to every output, and because
float32 `tanh` saturates around ±9 while the logits reach ±300, 69 % of rows had at least two of the
three forward-move logits collapse to the *same* float. `argmax` then picked by array order rather
than by value, and 1.2 % of forward/back decisions silently disagreed with torch. It was found by
arithmetic comparison, not by watching the bot — which is the whole point of this gate.

`Mlp` currently has only `zeros()` and `pseudo(seed)`. **There is no loader for `policy.bin` yet.**
Writing it is part of this task.

## Scope

- `rtx/crates/rtx-nav/src/automaton.rs` — add the loader. This is the right home: `Mlp` lives here
  and the live bot will need it too.
- `rtx/crates/rex-env/` — a small binary that runs the comparison.
- `pipeline/export_policy.py` — extend the existing `--check` path.

Do not touch `rtx-game` or anything under `bot/`. Never run `cargo fmt` in this tree.

## 1. The loader

`policy.bin` layout, from `pipeline/out/policy/policy.json`:

```
w0[NH*NIN] b0[NH] w1[NH*NH] b1[NH] w2[NOUT*NH] b2[NOUT]   little-endian f32
```

For the shipped policy `NIN=14, NH=256, NOUT=8`, which is 71 688 floats = **286 752 bytes**. The
loader must reject a file whose length is not exactly `4 * (NH*NIN + NH + NH*NH + NH + NOUT*NH +
NOUT)` for its const generics rather than reading whatever happens to be there — a silently
half-loaded network is the same class of bug as the `tanh` one.

Row-major convention must match `export_policy.py`. Read that file; do not guess. If the export and
the loader disagree on row-major vs column-major the parity test below will fail loudly, which is
the intended safety net, but check first.

## 2. The comparison

Rather than embed torch in Rust or Rust in Python, compare through a file:

1. Python writes a held-out batch: **at least 100 000 rows** of the 14-dim observation, from the
   test split the policy never trained on, plus torch's decoded actions
   (`fmove`, `smove`, `dyaw`, `jump`) and the raw 8 logits.
2. A Rust binary in `rex-env` loads `policy.bin`, runs the same rows through `Mlp::forward` and
   `automaton::decode`, and writes its own decoded actions and logits.
3. Python compares and prints a per-field report.

Use a plain, self-describing binary or `.npy`; do not invent a format that needs a parser on both
sides if a trivial one will do.

## 3. The gate

| quantity | threshold |
|---|---|
| `fmove` agreement | **100.000 %** of rows |
| `smove` agreement | **100.000 %** of rows |
| `jump` agreement | **100.000 %** of rows |
| `dyaw` max absolute difference | **<= 1e-5** |
| logit max absolute difference | **<= 1e-3** |

The discrete heads must agree *exactly*. Anything less means an `argmax` tie is being broken
differently on the two sides, and a tie-break that depends on array order is a latent version of the
bug this gate exists to catch. If you find genuine ties in the logits, report them — do not paper
over them by loosening the threshold.

`dyaw` and the logits get a tolerance only because f32 accumulation order legitimately differs
between BLAS and a hand-rolled loop.

## 4. If it fails

Report the failure with numbers. Do **not** adjust the thresholds, and do not "fix" it by making the
Rust side round or clamp toward the Python side. The likely causes, in order: row-major/column-major
mismatch, an activation applied in the wrong place (the `tanh` bug's shape), and f32 vs f64
accumulation in the hidden layers.

## Done when

`cargo test -p rex-env` and `cargo test -p rtx-nav` pass, the comparison binary runs on >= 100 000
held-out rows, and every threshold in §3 is met. Write the report to
`evidence/g0.2_parity.json` with the row count and every measured number, whether it passed or not.

## Reporting

Report the measured numbers, not a verdict. Report anything in this spec that was wrong or
under-specified.
